# 启动排查

## 工作台打不开

1. 检查 `alx` 启动终端是否仍在运行，有没有启动错误。
2. 使用终端实际显示的地址与端口；如果修改了端口，不要继续访问默认地址。
3. 检查工作台健康与环境：

```bash
alx health
alx doctor
```

后台服务可使用 `alx status` 与 `alx logs` 检查。手动下载后提示命令不存在时，按 [安装](/docs/alemonx/getting-started/install) 从程序所在目录启动。

## 机器人项目启动失败

先确认操作的是目标项目，再查看依赖安装和启动输出中的第一处错误：

| 线索               | 下一步                                             |
| ------------------ | -------------------------------------------------- |
| 找不到依赖或运行时 | 核对项目 README 的环境要求并完成依赖安装           |
| 端口占用           | 检查已有进程与项目端口配置，避免重复启动           |
| 缺少配置或凭据     | 对照框架和相关插件的配置说明                       |
| 加载的仍是旧代码   | 核对启动入口是否指向编译产物，并执行项目的构建脚本 |

## 机器人进程停在 CBP 握手或应用初始化

从 AlemonJS 2.1.122 起，应用进程先完成 CBP 传输握手，再启动应用 HTTP 服务并加载应用。使用框架的进程管理器时，可根据阶段或超时日志定位问题。

| 日志或状态                                     | 检查项                                                                                |
| ---------------------------------------------- | ------------------------------------------------------------------------------------- |
| `transport_ready_timeout`                      | 确认主进程或外部 CBP 服务可用，核对连接方式、地址和端口，并检查子进程最早的错误日志。 |
| 日志提示「业务初始化较慢，尚未收到 app_ready」 | 传输握手已完成。查看后续的模块加载和初始化日志，检查应用入口、依赖和生命周期回调。    |
| 已出现 `app_ready`                             | 应用进程完成启动。还需查看适配器自己的登录和连接状态。                                |

默认传输就绪超时为 15 秒，应用初始化超过 30 秒时默认记录告警。确需调整启动耗时时，在 `alemon.config.yaml` 的 `process.transport_ready_timeout` 或 `process.app_ready_timeout` 填入毫秒数。

## 运行成功但没有回复

工作台健康、进程存活与消息收发是不同的检查。继续按 [消息排查](/docs/help/messages) 检查入站、路由和出站阶段。
