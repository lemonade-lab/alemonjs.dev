# Agent 任务状态机与审批机制

ALemonX 把 Agent 的一次工作分成“任务计划”和“工具调用”两层。计划审批回答“是否允许做这件事”；工具审批回答“这一次具体的写入、执行或发布是否允许”。两者不能互相替代。

## 任务生命周期

```text
                  编辑计划
                     │
                     ▼
created ───────▶ plan_pending ──批准──▶ queued ──启动──▶ running
                     ▲                    │              │
                     │拒绝/修改           │取消           │
                     │                    ▼              ▼
                     └─────────────── cancelled     paused
                                                       │
                                      用户恢复 ─────────┘

running ──验证通过──▶ completed
running ──失败──────▶ failed ──重试/恢复──▶ queued
```

终止状态为 `completed`、`failed` 或 `cancelled`。进程重启会将不可安全续接的 `running` 任务转为 `paused`，恢复操作必须重新进入任务边界；不会自动恢复尚未重新授权的写操作。

## 计划结构

计划至少包含目标、完成条件和一个或多个步骤。标准步骤按 `understand → implement → verify` 推进；验证失败停留在当前步骤，并保留输出、快照和报告。

```json
{
  "goal": "修复机器人启动错误",
  "completion": "项目可以通过受控验证并成功启动",
  "steps": [
    { "id": "understand", "status": "pending" },
    { "id": "implement", "status": "pending" },
    { "id": "verify", "status": "pending" }
  ]
}
```

修改待审批计划会清除原批准并回到 `plan_pending`。重试失败执行不等于修改计划，但如果目标、步骤或验证命令改变，必须重新审批。

## 审批规则

| 操作                                    | 默认行为                       | 原因                   |
| --------------------------------------- | ------------------------------ | ---------------------- |
| 读取项目、查看日志、查询状态            | 可直接执行                     | 不改变项目或主机状态   |
| 创建任务、修改项目计划                  | 计划审批                       | 明确执行范围和完成条件 |
| 写文件、安装依赖、启动/停止服务         | 工具级确认                     | 产生项目或进程副作用   |
| npm 发布、Git Release、系统插件特权操作 | 强制确认                       | 影响外部系统或主机     |
| 定时 Goal、自动运维                     | 受策略、白名单、租约和预算约束 | 防止无人值守扩大权限   |

HTTP 审批入口为 `POST /api/v1/agent/approve`。客户端必须展示真实的确认界面；`confirm: true` 是本次调用的用户确认，不是永久授权。

## 并发、租约与取消

同一项目的写任务通过项目级租约互斥。取消会停止后续步骤并持久化事件；若子进程无法立即退出，任务仍会保留取消状态与诊断信息。任务检查点、事件、快照和报告使用本地持久化，便于恢复和审计。

## 给集成方的建议

集成 Agent 时应先读取任务状态，再根据 `status` 决定下一步；不要通过重复创建任务实现轮询，也不要把 `failed` 当成 `completed`。长操作应订阅 SSE 或轮询任务详情，并展示验证输出、拒绝原因和最后一个可恢复检查点。
