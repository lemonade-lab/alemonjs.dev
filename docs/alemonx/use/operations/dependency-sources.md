# 依赖源管理

ALemonX 将依赖源视为系统配置事务，而不是简单的下载加速开关。当前版本的系统依赖源管理以**只读预检**为主，不会自动追加、切换或恢复发行版仓库。

## 当前策略

| 平台     | 当前能力                                  | 不会做什么                                          |
| -------- | ----------------------------------------- | --------------------------------------------------- |
| DNF/YUM  | 检查镜像元数据，识别 ALemonX 遗留仓库文件 | 不追加新的 BaseOS/AppStream 仓库，不修改系统仓库 ID |
| APT      | 识别带 ALemonX 所有权标记的旧 drop-in     | 不自动写入或恢复不兼容的源配置                      |
| 其他平台 | 提供环境和网络诊断                        | 不猜测发行版配置并自动写入                          |

## 为什么不直接追加镜像

系统原仓库与镜像仓库的元数据可能并非完全同步。为同一软件包新增第二个仓库 ID 会让求解器同时面对不同构建，可能造成组件冲突。`--allowerasing`、`--nobest` 和 `--skip-broken` 不能解决根因，不应被用来掩盖冲突。

## 遗留文件清理

如果发现带有 ALemonX 所有权标记的固定遗留文件，工作台会先展示路径和备份信息，用户确认后才备份并移除。没有所有权标记的同名文件不会被删除；备份用于审计，当前 MVP 不提供自动写回恢复。

## 运维建议

先执行元数据预检，再检查发行版仓库、第三方仓库和包管理器错误。公开网络部署工作台前应开启认证并限制管理端访问。机器人项目自身的 npm/Yarn/pnpm 依赖与系统 DNF/APT 源是两条不同链路，不要混用排障结论。
