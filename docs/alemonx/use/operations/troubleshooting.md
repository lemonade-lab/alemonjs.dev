# 故障排查

## 先收集诊断信息

```bash
alx status
alx health
alx doctor
alx logs --lines 200
```

前台运行时查看启动它的终端；后台服务日志可用 `alx logs` 查看。

## 浏览器无法打开

确认工作台正在运行，并检查监听地址：

```bash
alx health --port 17390
alx --host 127.0.0.1 --port 17390
```

当前默认监听 `0.0.0.0`。如果只需要本机访问，应显式指定 `127.0.0.1`；如果开放到局域网或公网，必须先启用认证并配置防火墙。

## 端口被占用

为工作台指定其他端口：

```bash
alx --port 17391
```

机器人端口、测试端口和内置 Redis 端口是不同配置。Redis 可以使用 `--redis-port` 调整，或使用 `--redis-off` 关闭。

## 机器人启动失败

按顺序检查：

1. Node.js、Git 和包管理器是否通过“环境”检查；
2. `package.json` 的启动脚本是否存在；
3. 依赖是否安装完成；
4. `alemon.config.yaml` 的平台配置和端口是否正确；
5. 是否已有前台进程或 PM2 进程占用端口。

开发模式适合查看完整错误；PM2 模式请同时查看状态和日志。

## Agent 操作失败

先查看任务计划、事件和验证输出。不要直接重复批准写入操作：

- 检查任务是否仍持有项目租约；
- 确认目标目录在允许范围内；
- 确认依赖安装或构建命令没有失败；
- 查看检查点或报告，再决定恢复、回滚或重新创建任务。
